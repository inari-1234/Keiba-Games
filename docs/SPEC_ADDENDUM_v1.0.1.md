# 仕様追補 v1.0.1（第1版 Codex実装仕様書 v1.0 への追補）

基準日：2026年9月29日。v1.0 の記述と矛盾する場合は本追補を優先する。

## A1. 組み合わせオッズ（仕様15の具体化）
- 単勝オッズ（固定）から各馬の勝率を逆算し、Harville方式で全組み合わせの確率を算出して固定値を事前生成する。
- 控除率：単勝・複勝20%、馬連・ワイド22.5%、馬単・三連複25%、三連単27.5%。
- 0.1倍未満は切り捨て、最低1.1倍。上限は設けない。
- 内部表現は0.1倍単位の整数（例：48 = 4.8倍）。払戻 = 購入額 × オッズ。購入額が100pt単位のため払戻は常に10pt単位の整数となり、端数処理は発生しない。
- 生成スクリプト：`tools/generate_odds.py`。生成物：`OddsTable+Generated.swift`（手編集禁止。CIで最新か検証）。

## A2. 勝率の校正（仕様20・24の補強）
- 1万レース（seed 1〜10000）の各馬の勝率が、単勝オッズの示す確率と許容誤差 max(1.5pt, 期待値の20%) 以内で一致すること。
- 目的：特定の馬を買い続けるだけで勝てる「必勝法」を作らない。
- 内部能力値 speed はこの条件を満たすよう `tools/prototype` で校正済み。

## A3. 固定シードの扱い（仕様25の具体化）
- 乱数の初期値は `seed XOR (Race.salt × 0x9E3779B97F4A7C15)` とする。salt はレース固有値。
- salt は、DEBUGの固定シード 20260927 で参考画像の着順（3-6-1-8-5）になる値（2029）を選定した。能力値や数式を着順に合わせて歪めてはいない。
- RaceEngine の数式・演算順は `tools/prototype/engine.py` と一致させる。数式を変更する場合は、プロトタイプで再校正し、speed と salt を更新する。

## A4. 枠色（仕様4・36の矛盾解消）
- 馬番の色 = 仕様36の枠色（1白〜8桃）。9・10番は馬番表示側で識別する。
- 出走表の「枠番」列は表示しない（馬番=色で代替）。

## A5. 残高の保存と救済
- 所持ポイントは端末内に保存し、次回起動時も引き継ぐ。
- 残高が100pt未満で、かつ未精算の馬券がないときに限り、「12,300ptで再スタート」ボタンを表示する。押すと残高を12,300ptに戻す。
- 保存に失敗しても、12,300ptで開始できること（仕様40）。

## A6. 称号
残高に応じて称号を表示する（表示のみ。ゲーム結果には影響しない）。

| 50,000pt〜 | 腕利き予想家 |

## A7. 検証環境
- ロジック層は Swift Package `KeibaCore`（UI非依存）として分離し、`swift test` で検証する。
- アプリのビルド（Debug/Release）・テスト・シミュレータのスクリーンショット取得は GitHub Actions の macOS ランナーで行う（`.github/workflows/ios-ci.yml`）。
- Xcodeプロジェクトは XcodeGen（`project.yml`）から生成する。
